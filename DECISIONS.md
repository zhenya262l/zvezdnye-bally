# Технические решения

Одна строка — одно решение: что выбрано и почему.

## Этап 1. Каркас

- Expo SDK 57 и Expo Router, веб-сборка `output: single`. Один index.html, экраны рисуются на телефоне, сервер для страниц не нужен.
- Адрес подпапки `/<repo>` задаётся при сборке через `EXPO_BASE_URL`. GitHub Pages публикует проект по адресу `имя.github.io/<repo>/`.
- `404.html` — копия `index.html`. GitHub Pages отдаёт её на любой адрес внутри приложения, и открывается нужный экран.
- Service worker собирается из `sw/sw.ts` через esbuild и Workbox `injectManifest`. Нужен свой код для пушей на этапе 2, готовый `generateSW` его не допускает.
- Новая версия service worker включается сразу и показывается при следующем открытии приложения. Так требует раздел 10.
- Клиент только читает данные под правилами RLS. Все записи идут через функции Postgres с проверкой роли. Так ребёнок не может ничего изменить напрямую.
- Привязка телефона `pair_device` — функция Postgres, а не Edge Function. Это одна транзакция и не нужен отдельный деплой. Edge Functions понадобятся для пушей и Face ID.
- Код привязки: 6 цифр из криптостойкого генератора, в базе хранится только хеш SHA-256. Код одноразовый, живёт 10 минут, работает только последний выданный.
- Защита от подбора кода: не больше 5 неверных попыток за 10 минут с одного телефона. Общий предел со всех телефонов на этапе 2 поднят с 50 до 300 (см. ниже).
- `pair_device` возвращает ошибку в ответе, а не исключением. Иначе откатилась бы запись о неудачной попытке и защита от подбора не работала бы.
- Телефон ребёнка входит анонимным аккаунтом Supabase. Почта ребёнку не нужна, вход постоянный.
- Отвязка телефона удаляет его анонимный аккаунт. Доступ к данным пропадает сразу, сессия телефона перестаёт обновляться.
- Родитель входит по 6-значному коду из письма. Ссылка из письма открылась бы в Safari, а не в установленном приложении.
- В Supabase меняются два шаблона письма: «Confirm signup» для первого входа и «Magic Link» для следующих. На локальном стенде проверено: при первом входе приходит письмо подтверждения.
- Имена и даты рождения детей не записаны в код. Родитель вводит их при создании семьи, потому что репозиторий публичный.
- `SPEC.md` исключён из репозитория через `.gitignore`. В нём данные семьи.
- Comfortaa — только для надписей заглавными буквами, заголовки набраны Nunito ExtraBold. Строчные кириллические «д, т, и, п» в Comfortaa похожи на «g, m, u, n» и мешают детям читать.
- Шрифты подключаются по отдельным начертаниям, всего 6 файлов. Иначе в сборку попадали все начертания и приложение весило на 2 МБ больше.
- Подпись под значком на экране «Домой» — «Звёзды». Полное «Звёздные баллы» iPhone обрезает.
- Увеличенный шрифт iOS: страница получает системный шрифт `-apple-system-body`, приложение читает его размер и увеличивает свои шрифты до 1,6 раза.
- Подтверждения «Отвязать», «Выйти» и «Удалить» — свои окна в приложении. Системные `alert` в веб-версии React Native не работают.
- Удаление семьи требует ввести слово УДАЛИТЬ. С этапа 3 к нему добавится Face ID или ПИН.
- На этапе 1 родитель после входа попадал на вкладку «Дети». С этапа 2 стартовая вкладка — «Ждут подписи».
- Ребёнок видит записи родителей (понадобится для «Подтвердила мама»), но не видит профиль и телефон сестры.
- «Сегодня» считается на сервере по часовому поясу семьи Europe/Minsk. Поэтому дату рождения нельзя поставить в будущем.
- Окно «Код для телефона» понимает, что телефон подключился, по времени привязки на сервере. Подсчёт телефонов давал гонку, если ребёнок вводил код очень быстро.
- Локальный стенд для проверок: настоящие Supabase Auth v2.195.0 и PostgREST v12.2.3 со встроенным Postgres. Так всё проверяется до подключения настоящего проекта.
- Сборка и публикация — GitHub Actions и `actions/deploy-pages`. Отдельная ветка `gh-pages` не нужна.
- Адрес и публичный ключ Supabase хранятся в переменных репозитория GitHub, а не в коде. Публичный ключ виден в приложении по замыслу Supabase, данные закрыты правилами RLS.
- Письма с кодом уходят через Gmail владельца (SMTP smtp.gmail.com:465, пароль приложения Google). Без своего SMTP Supabase не даёт менять шаблоны и шлёт ссылку вместо кода, а встроенная почта пишет только адресам команды и не больше 2 писем в час.
- Длина кода из письма выставлена 6 цифр. У новых проектов Supabase по умолчанию 8.
- В проекте Supabase выключено «Automatically expose new tables». Права на таблицы и функции миграция выдаёт явно.
- Значки приложения генерируются заново при каждой сборке в GitHub Actions. При переносе файлов на компьютер в картинки добавляются метаданные C2PA, в сборку они не попадают.
- Приглашение второго родителя перенесено на этап 2. Его нет в списке этапа 1.
- Face ID и ПИН родителя — этап 3, как в разделе 11. Модули `src/platform/push` и `src/platform/biometric` уже выделены с одним интерфейсом.

## Этап 2. Дела и подписи

Выложено на сайт и в рабочую базу 20.10.2026, после проверки этапа 1 на двух iPhone. Пуши — следующим шагом.

- Баллы появляются только как запись в журнале `ledger`. Журнал только дополняется: запись нельзя изменить или удалить. Ошибку исправляет новая запись «Исправление» с обязательным комментарием.
- Баланс — сумма записей журнала. Ниже нуля он не опускается. Проверка стоит в той же функции, которая пишет в журнал.
- Баллы за дело берутся из его настроек в момент подписи. Если родитель изменил баллы днём, заявка засчитывается по новому значению.
- Одно дело — одна заявка в день. Повторное «Сделала» не создаёт вторую заявку. Повторная подпись не начисляет баллы второй раз.
- Если два родителя нажали «Подписать» одновременно, засчитывается первая подпись. Второй видит, кто уже подписал. Своё собственное решение повторно не показывается как «Уже решено».
- Все подписи блокируют строки в одном порядке: сначала ребёнка, потом заявку. Так одновременные подписи двух родителей и быстрые нажатия «Сделала» ждут друг друга, а не обрываются ошибкой.
- Проверка родителем по умолчанию выключена (решение владельца 19.10.2026). Баллы за дело начисляются сразу после «Сделала». Родитель включает проверку у отдельного дела прямо в списке «Дела и баллы» или сразу для всех дел ребёнка. Трата баллов (этап 3) будет всегда с подписью родителя.
- Засчитанное сразу дело видно родителю в «Решено сегодня» с пометкой «Засчитано сразу, без проверки». Там же его можно похвалить.
- Стартовый набор — 24 дела в 5 разделах дневника. «Не опоздала в школу» стоит только на Пн–Пт, остальные дела — каждый день. Родитель меняет набор в «Настройки → Дела и баллы».
- Значки дел — эмодзи из набора на 40 штук. Отдельные картинки не нужны, эмодзи есть на любом телефоне.
- Если у дела задано окно времени, «Сделала» работает только в этом окне. До его начала ребёнок видит, с какого часа можно отметить дело.
- На экране «Сегодня» разделы дневника свёрнуты, на полосе раздела виден счёт «2 из 8». Ребёнок раскрывает раздел касанием. Какие разделы открыты, телефон запоминает. Это замена «мягкого старта» с 6–8 делами (решение владельца).
- В разделе сначала дела, которые можно сделать сейчас, потом ждущие подписи, потом дела на более позднее время, в конце дела с прошедшим временем. Засчитанные и незасчитанные дела сворачиваются в строку «Сделано: N».
- Похвала: родитель одним касанием выбирает «Умница!», «Молодец!», «Горжусь тобой!» или «Так держать!» у засчитанного дела. Ребёнок видит похвалу под делом и в истории баллов. Повторное касание заменяет похвалу.
- Сюрприз-бонус — только кнопка родителя на вкладке «Дети». По умолчанию 3 балла, родитель выбирает от 1 до 50 и пишет, за что. В списке дел ребёнка бонуса нет.
- «Подписать всё за сегодня» подписывает только сегодняшние заявки. Вчерашние родитель подписывает по одной.
- В «Решено сегодня» последняя подпись стоит сверху.
- Какие заявки «сегодняшние», решает сервер по часовому поясу семьи. Поэтому сразу после полуночи кнопка «Подписать всё за сегодня» не показывает вчерашние заявки.
- Экраны «Сегодня», «Ждут подписи» и «Дети» запрашивают сервер раз в 3 секунды, пока приложение открыто. При возврате в приложение данные обновляются сразу. Supabase Realtime не понадобился: на стенде баллы появлялись у ребёнка через 1–4 секунды после подписи.
- Код приглашения второго родителя — 6 цифр, действует 10 минут, срабатывает один раз. Второй родитель входит по своей почте и вместо создания семьи вводит код. Код для телефона ребёнка родителем не делает.
- Изменения дел и разделов записываются в журнал настроек `settings_audit`.
- На вкладке «Дети» у ребёнка с подключённым телефоном видно «✓ Телефон подключён». Большой кнопки подключения больше нет, вместо неё тихая ссылка «Подключить другой телефон» на случай нового телефона. Отвязать телефон можно во вкладке «Семья».
- Удалённое дело пропадает из списков. Старые заявки и записи журнала сохраняют его название и значок.
- Записи журнала удаляются только вместе со всей семьёй. Удаление заявки, дела, раздела или ребёнка баллы не стирает. Серверный ключ (понадобится для пушей) журнал только читает.
- Копирование дел на сестру обновляет дела с тем же названием на месте. Сегодняшние отметки сохраняются, и одно дело нельзя сделать дважды за день. Повторное нажатие не создаёт второй список.
- В семье не больше двух родителей, как в SPEC. Приглашение и вход второго родителя записываются в журнал настроек.
- Неверные коды для телефона ребёнка и для второго родителя считаются отдельно. Общий предел для телефонов — 300 неверных кодов за 10 минут. Вероятность угадать живой код за это время — 0,03 %. Чтобы заблокировать подключение для всех, постороннему понадобится много разных адресов: Supabase пускает не больше 30 анонимных входов в час с одного адреса.
- Названия дел, разделов и комментарии очищаются от пробелов, переносов строк и невидимых символов по краям. Пустое название не сохраняется.
- Клиент может вызывать только три вспомогательные функции, которые нужны правилам RLS. Баллы и подписи меняются только через функции с проверкой роли.
- Пуши (Web Push) — после проверки этапа 1 на iPhone. До этого заявки видны на экране «Ждут подписи» без уведомлений.
- Вибрация после подписи работает только на Android. Веб-приложения на iPhone вибрировать не могут: в Safari нет такой возможности. На iPhone остаются летящая звезда и обновлённый баланс.
- Если ребёнок прокрутил список вниз, звезда летит к значку баланса, который на 2–3 секунды появляется вверху экрана. Если ребёнок был на другой вкладке, звезда летит, когда он вернётся на «Сегодня».
- Формула дня — строкой на широком экране с обычным шрифтом. На узких iPhone (375 точек), с крупным шрифтом iOS или в день исправления она показывается столбиком, как сложение в тетради. Так подписи не обрезаются.
- Исправление родителя показано в формуле отдельной строкой «Исправление». Это не «Потратила».
- Ошибка после «Сделала» показывается прямо под этим делом. На длинных экранах родителя сообщения всплывают внизу экрана. Так их видно, даже когда кнопка далеко внизу списка.
- Без интернета «Сделала» сразу сообщает «Нет связи». Нажатие не отправляется позже само: иначе оно могло бы уйти уже на следующий день или после окончания времени дела.
- Текст на цветном фоне (полосы разделов, бирюзовые и коралловые кнопки, выбранные варианты) — тёмно-синий или белый, смотря что читается лучше. Белый на бирюзовом и коралловом читался плохо.
- Общие сообщения об ошибках написаны без «ты» и «вы»: их видят и дети, и родители.
- На экранах родителя «‹ Назад» стоит и вверху. У приложения на экране «Домой» нет кнопки «Назад» браузера.
- Фото к делу — после пушей, по решению владельца.

## Новые семьи только с одобрения владельца

Решение владельца 19.10.2026. Выложено 20.10.2026 вместе с этапом 2.

- Новый родитель входит по почте и видит не создание семьи, а заявку. В заявке полный текст согласия на обработку персональных данных и галочка «Я прочитал(а) текст и даю согласие». Без галочки заявка не отправляется.
- Владелец приложения одобряет или отклоняет заявку во вкладке «Семья» → «Новые семьи». Только после одобрения родитель может создать семью. Отклонённую заявку владелец может одобрить позже.
- Владелец (администратор) задаётся один раз командой в базе по его почте, не в коде. Почта владельца в публичный репозиторий не попадает.
- Текст согласия хранится в базе, а не в коде: в нём ФИО и адрес оператора. Владелец меняет его в приложении, «Семья» → «Новые семьи» → «Текст согласия». Каждое сохранение создаёт новую редакцию, старые не меняются и не удаляются.
- У каждого родителя хранится номер редакции и время согласия. Второй родитель, который входит по коду приглашения, даёт такое же согласие. Отдельного одобрения владельца ему не нужно: семья уже одобрена.
- Если текст согласия обновился, пока родитель читал старую редакцию, отправка не пройдёт и приложение покажет новую редакцию.
- Удаление семьи (отзыв согласия) удаляет и заявку. Чтобы вернуться, нужна новая заявка.
- Пока текста согласия в базе нет, новые семьи и вторые родители не могут продолжить. Поэтому при выкладке текст сохраняется до приглашения второго родителя.
- Уведомлений владельцу о новых заявках пока нет. Они появятся вместе с пушами. До этого список заявок обновляется раз в 30 секунд, пока открыта вкладка «Семья».
- Черновик текста согласия подготовлен отдельным документом для проверки владельцем. Сверить его с образцами НЦЗПД автоматически не удалось: сайт cpd.by закрыт для автоматического чтения.

## Проверка этапов 1 и 2 (октябрь 2026)

По просьбе владельца проверены ошибки, логика, дизайн каждого экрана, нестыковки и ссылки. Изменения в миграции 20261021000100_review_fixes.sql и в приложении.

- Если приложение открыли без интернета после долгого перерыва, сохранённый вход не теряется. Вместо «Кто ты?» видно «Нет связи… Вход сохранён», и приложение открывается само, когда связь появится.
- Экраны, открытые по ссылке или после перезагрузки, ждут сохранённый вход и не перебрасывают на вкладку «Подписи».
- Телефон ребёнка, который уже подключён, никогда не выходит из аккаунта при вводе нового кода.
- Неизвестный адрес показывает русский экран «Такого экрана нет» с кнопкой на главный экран.
- С крупным шрифтом iPhone две кнопки рядом («Подписать» и «Не засчитать», «Одобрить» и «Отклонить», «Включить» и «Выключить», «Отвязать») становятся одна под другой. Иначе слова ломались посередине. Нижняя панель вкладок растёт вместе с подписями.
- Недоступная кнопка серая с читаемым текстом в обеих темах. Раньше в тёмной теме был тёмный текст на тёмно-красном.
- «Не засчитано» не считается в «Сделано»: раздел показывает только засчитанные дела, а строка свёрнутых дел пишет, например, «Сделано: 4 · не засчитано: 1».
- После изменения баллов дела у засчитанного дела показано, сколько ребёнок получил на самом деле.
- Дело, отмеченное сегодня, остаётся на «Сегодня» до конца дня, даже если родитель его выключил или удалил.
- «Решено сегодня» показывает и вчерашние заявки, подписанные сегодня утром. Их видит второй родитель и их можно похвалить.
- Если заявку уже решил другой родитель, сообщение говорит, кто, что и во сколько: «Уже подписано: Мама, 19:42».
- Опрос сервера раз в 3 секунды идёт только на открытом экране. Скрытые вкладки не опрашивают. Список подключённых телефонов обновляется раз в 15 секунд.
- Пока список телефонов не загрузился, приложение не пишет «Телефон не подключён».
- Галочка согласия привязана к редакции текста. Если владелец сохранил новую редакцию, пока человек читал старую, галочка снимается.
- Подавший заявку может отозвать её вместе с согласием: «Отозвать заявку и согласие». На экране ожидания и отказа есть «У меня есть код приглашения».
- Кто вошёл в семью по коду приглашения, того заявка удаляется: согласие хранится у участника семьи. В списке «Новые семьи» сначала ожидающие заявки, решённые свёрнуты.
- «Пригласить второго родителя» скрыто, когда в семье уже два родителя.
- Лимиты «два родителя» и «шесть детей» проверяются под блокировкой семьи: двойное нажатие не создаёт два живых кода приглашения.
- Попытки ввода кода проверяются по одной. Параллельные запросы с одного телефона не обходят лимит в 5 попыток. Записи о попытках старше суток удаляются.
- Текст согласия не выдаётся на телефоны детей.
- Таймер кода считает 10 минут от получения кода на этом телефоне. Неверные часы телефона больше не показывают «Код устарел» сразу.
- Голосовой помощник VoiceOver теперь слышит состояние элементов: раздел открыт или закрыт, вариант выбран, галочка стоит. Цвета называются словами, у стрелок порядка есть название дела.

### Решения владельца 20.10.2026 об отзыве согласия

- Второй родитель может сам «Выйти из семьи». Его вход по почте, участие в семье и согласие удаляются. Дети, дела и история остаются у другого родителя. Последний родитель отзывает согласие удалением семьи.
- Удаление семьи удаляет и учётные записи родителей с почтой. Учётная запись владельца приложения остаётся: она нужна, чтобы одобрять новые семьи.
- «Отозвать заявку и согласие» удаляет и учётную запись того, кто подал заявку.
- Убрать другого родителя из семьи нельзя: это решается в самой семье.
- Новую редакцию согласия родители, которые уже в семье, принимают при следующем открытии приложения. До этого вкладки родителя не открываются. Владелец приложения и дети не видят этот экран. Кто не согласен, может выйти из семьи или удалить её прямо с этого экрана.
- Повторное согласие проверяется в приложении, а не в каждой функции базы. Для семейного приложения этого достаточно, а функции базы остаются проще.
- Имя ушедшего родителя в истории подписей заменяется словами «другой родитель». В журнале настроек остаётся только факт выхода, без имени.
- На рабочем проекте проверено: роль postgres может удалять учётные записи (has_table_privilege = true), хотя не является суперпользователем. Значит, удаление работает и вне тестового стенда.
- Текст согласия, редакция 1, дополнен по решению владельца 20.10.2026 без нового номера редакции: её ещё никто не принимал (проверено в той же команде). Добавлены выход из семьи (п. 9.2), отзыв заявки (п. 9.3), сроки удаления после выхода (п. 7) и последствия выхода (п. 10). Защита от изменения старых редакций включена обратно сразу после правки. Дальше любые изменения — только новой редакцией.

## Пуши (этап 2, последняя часть)

Начато 21.10.2026 по команде владельца.

- Web Push по SPEC, раздел 8. Подписка появляется только после нажатия «Включить уведомления»: на iPhone без нажатия запроса разрешения не будет.
- Отправляет серверная функция Supabase `push` (supabase/functions/push). Она берёт сообщения из очереди в базе, шифрует их (aes128gcm) и отдаёт службе доставки телефона. Библиотека web-push 3.6.7 с npm: проверенная временем, работает в Deno.
- База будит функцию сразу после события через pg_net и раз в минуту через pg_cron: сводки, отложенные сообщения, повторы. Вызов функции защищён общим секретом, который база создала сама. Ключи Supabase для этого не нужны.
- Ключи VAPID функция создаёт сама при первом запуске. Закрытый ключ лежит в Supabase Vault, открытый — в базе. Никто не вводит ключи руками.

- Вечерняя сводка по умолчанию в 20:00, тихие часы 21:00–07:00. Оба времени каждый родитель меняет в «Настройки» → «Уведомления». В тихие часы новые заявки не будят, а в конце тихих часов приходит утренняя сводка. Сводка приходит, только если есть что подписать.
- Ребёнку (решение владельца 21.10.2026): ответ на заявку, сюрприз-бонус, похвала. Ночью, в те же тихие часы, ребёнку пуши не приходят: результат она увидит в приложении.
- Если родитель подписал сразу несколько дел, ребёнку приходит одно уведомление: «⭐ Засчитано 5 дел: +9 баллов».
- Владельцу приложения: новая заявка на семью. Ночью она ждёт конца тихих часов.
- В уведомлениях нет пола родителя: «подпись: Мама», а не «Мама подтвердила». Имя «Папа» по окончанию не отличить от женского.
- Если уведомления запрещены, карточка показывает путь в Настройках iPhone. Кнопка «Проверить уведомление» шлёт пробный пуш, не чаще 5 раз за 10 минут.
- При выходе из аккаунта телефон отписывается. Подписки удаляются вместе с учётной записью. Телефон, который уже разрешил уведомления, при запуске снова сообщает серверу свою подписку.
- Если служба доставки отвечает 404 или 410, подписка удаляется. Если она занята (429, 5xx) или недоступна, сообщение ждёт две минуты и пробуется снова, до 5 раз.
- Ключ телефона проверяется через WebCrypto до шифрования: испорченный ключ ронял среду выполнения Deno целиком, а не только отправку.
- Нажатие на уведомление при открытом приложении переключает экран без перезагрузки. Если приложение закрыто, оно открывается сразу на нужном экране.
- Тексты уведомлений написаны в базе рядом с событиями, а не в src/strings.ru.ts: их собирает сервер.
- Пуши идут через службу Apple (США), а на Android — через Google (США), в зашифрованном виде. По решению владельца 21.10.2026 это внесено в редакцию 1 согласия без новой редакции (её никто не принимал): п. 3.3, 4.1, 4.2, новый п. 6.4 и абзац о передаче в США.
- Проверки: 8 тестов базы для пушей, 3 теста функции с поддельной службой доставки (она расшифровывает сообщения ключами «телефона» и проверяет подпись VAPID), 3 сценария в браузере. Настоящая доставка на iPhone проверяется только на телефоне.
- Проверено на iPhone владельца 21.10.2026: пробное уведомление и уведомление о заявке пришли, нажатие открыло заявку, после подписи баллы долетели до телефона дочки. Этап 2 закрыт.

## Фото к делу (после пушей)

- В карточке дела переключатель «Нужно фото» (SPEC, раздел 6). В списке дел — отметка «📷 С фото», её можно переключить одним нажатием.
- Решения владельца 21.10.2026: без фото «Сделала» не отправляется. Фото хранится 7 дней после подписи или «Не засчитать», потом удаляется само.
- Дело с фото всегда с проверкой родителя: без подписи фото никто не посмотрит. Включили фото — проверка включилась. Выключили проверку (у дела или «для всех дел») — фото выключилось. Правило держит база, экраны повторяют его.
- Камера открывается сразу (`capture`), без выбора из галереи: снимок делается в момент дела. Телефон уменьшает фото до 1280 точек по длинной стороне, JPEG около 150–400 КБ. Сервер принимает только JPEG до 1 МБ.
- Фото хранятся в базе (закрытая таблица private.task_photos), а не в Supabase Storage. Причины: в рабочей среде Claude нельзя запустить сервер хранения Supabase для проверки, а в базе всё проверяется тестами. Фото видит только родитель семьи и сама дочка, через функцию task_photo. При удалении семьи, ребёнка или заявки фото удаляются сразу вместе с ними. Объём: при 2 детях и нескольких фото в день хранится около 10–20 МБ при лимите базы 500 МБ.
- Удаление через 7 дней — задание pg_cron раз в час (supabase/sql/photo_live.sql). Баллы и запись в истории остаются, пропадает только снимок.
- Родитель видит фото сразу в заявке, крупно — по нажатию. В истории баллов фото открывается по кнопке, пока не удалено.
- Родитель может удалить любое фото раньше срока: открыть фото → «Удалить фото» (решение владельца 21.10.2026, например если на снимок попал сам ребёнок). Заявка, баллы и запись в истории остаются. Ребёнок удалить фото не может. Это же записано в согласии, п. 4.
- Если открыть приложение старой версии, дело с фото не отметится, пока приложение не обновится: сервер требует фото.
- Проверки: 9 тестов базы (правило проверки, копирование дел, размер и формат, кто видит фото, удаление через 7 дней, удаление родителем, удаление с семьёй, закрытость таблицы), 2 сценария в браузере (большой снимок 4000×3000 уменьшается до 1280×960, удаление фото из истории, отмена без фото).

## Этап 3, часть 1: магазин

- Магазин общий на семью, стартовые 14 товаров из бумажного дневника. Значки товаров выбраны по смыслу (в SPEC их нет), родитель может поменять.
- «Лечь спать на 30 минут позже (пт, сб)» продаётся только в пятницу и субботу: доступность товара хранится днями недели, как у дел. «Только в выходные» = Сб и Вс, «скрыто» = переключатель «Товар в магазине».
- Покупка — заявка. Баллы списывает только сервер после подписи родителя, одной записью в журнале со ссылкой на покупку. Повторная подпись ничего не списывает.
- Запрет минуса: «Купить» принимается, только если баллов хватает с учётом других покупок, которые ждут подписи. При подписи сервер проверяет баланс ещё раз (например, если родитель тем временем исправил баллы).
- Покупка хранит название, значок и цену на момент заявки: смена цены не меняет ждущие и подписанные покупки.
- Родитель видит покупки сверху экрана «Подписи», отдельно от дел. «Подписать всё за сегодня» покупки не подписывает: для покупок по SPEC позже понадобится Face ID или ПИН (часть 3).
- Пуш родителям о покупке, пуш дочке об ответе (если у неё работают уведомления).
- Тип товара (мелкая радость или большая покупка) и минуты экрана уже хранятся, но лимиты пока не действуют: лимит мелких радостей и большие покупки за день — часть 2 (лимиты меняет родитель), экранные минуты и Face ID или ПИН — часть 3.
- Проверки: 8 тестов базы (стартовый магазин, редактор и журнал настроек, дни недели, покупка и подпись, двойная подпись, запрет минуса, доступ чужих, пуши, удаление семьи), 1 сценарий в браузере.

- Решение владельца 23.10.2026 о лимитах: денежных лимитов не будет. Ни 40 баллов в день на мелкие радости, ни больших покупок с заказом за день: дочки сами решают, на что тратить баллы, и учатся распоряжаться ими. Тормоз — подпись родителя на каждой покупке. Часть 2 этапа 3 отменена. Тип товара остаётся только для группировки в магазине.
- Остаётся лимит экранного времени (мультики и планшет вместе, по умолчанию 40 минут в день): это правило про здоровье, а не про деньги. Родитель меняет его сам. Делается в части 3 вместе с Face ID или ПИН.

## Этап 3, часть 3: ПИН и экранное время

- Решение владельца 25.10.2026: подпись покупки подтверждается 4-значным ПИНом родителя. Face ID (ключ входа) — позже, отдельным шагом. ПИН спрашивают только при подписи покупки. «Не подписывать» ПИН не требует.
- ПИН у каждого родителя свой. В базе хранится только его хеш (bcrypt), проверяет сама база. После 5 неверных попыток ПИН блокируется на 15 минут.
- Сменить ПИН можно со старым ПИНом. Забытый ПИН: выйти и войти снова по коду из письма, 10 минут после входа новый ПИН задаётся без старого.
- Первый раз, когда родитель подписывает покупку без ПИНа, приложение предлагает придумать ПИН и сразу подписывает.
- Экранное время: мультики и планшет вместе, по умолчанию 40 минут в день. Считаются подписанные и ждущие покупки за день, отклонённые минуты возвращаются. Родитель меняет лимит в «Настройках». Новое значение действует с завтрашнего дня (SPEC, раздел 4), запись в журнал настроек. 0 — экранные товары на сегодня не продаются.
- У товара есть поле «Минуты экрана». У «20 минут мультика» и «30 минут планшета» они уже стоят.
- Потолок цены поднят до 10 000 баллов. Мечта на год — около 3 000 (расчёт 25.10.2026: реально 200–260 баллов в неделю, на мечту откладывается около четверти).
- Тесты SPEC, раздел 7: двойное подтверждение, минус, доступ чужой семьи, смена статуса с телефона ребёнка, смена баллов за дело — есть. «Лимит 40» отменён владельцем. «Покупка из отложенных баллов» — в этапе 4 вместе с копилкой.
- Проверки: 5 тестов базы (ПИН и блокировка, смена ПИНа, экранное время, минуты и цены, закрытость ПИНов), 2 сценария в браузере.


## Этап 3, часть 4: Face ID для подписи покупок

- Решение владельца 25.10.2026: Face ID делается сейчас, последним шагом этапа 3. ПИН остаётся запасным способом.
- Face ID работает через ключ входа (passkey, WebAuthn). Лицо и биометрия не покидают телефон. Сервер хранит только открытый ключ, им нельзя войти или подписать.
- Включить Face ID можно только с ПИНом («Настройки» → «ПИН для покупок» → «Включить Face ID»). У одного родителя не больше 5 ключей. «Выключить Face ID» удаляет все его ключи, запись в журнале. Ключи и ПИН родителя удаляются, когда он выходит из семьи или семья удалена (и у аккаунта владельца приложения, который остаётся).
- Подпись: база выдаёт одноразовый вызов на 3 минуты, телефон подписывает его с Face ID, функция «passkey» проверяет подпись (библиотека SimpleWebAuthn). Подписанный вызов принимается один раз, только этим родителем и только 2 минуты.
- Функция «passkey» не проверяет вход сама: чей ответ, она узнаёт из строки вызова в базе. Номер вызова случайный и живёт 3 минуты.
- Кнопка Face ID показывается, только если телефон умеет Face ID или Touch ID и ключ уже включён. Если Face ID не прошёл, остаётся ПИН.
- Ключ привязан к адресу сайта zhenya262l.github.io. Если сайт переедет на другой адрес, Face ID придётся включить заново.
- Проверки: 5 тестов базы (включение только с ПИНом, одноразовость и 2 минуты, чужой родитель и ребёнок, выключение и закрытость таблиц, удаление с семьёй), 1 сценарий в браузере с виртуальным Face ID и настоящей функцией проверки.

## Этап 4, часть 1: копилка мечты

- Решения владельца 25.10.2026: мечту предлагает дочка (своими словами или большой покупкой из магазина), цену назначает и одобряет родитель. Отложенные баллы дочка может забрать, но потратить забранное можно только со следующего дня.
- Отложить баллы не значит потратить: журнал баллов не меняется, баланс тот же. Копилка — отдельный журнал движений (положила, забрала, вернулось при отмене, оплачено мечтой).
- В магазине можно потратить: баланс минус копилка, минус покупки, которые ждут подписи, минус баллы, забранные из копилки сегодня. Положила и забрала в тот же день — эти баллы и так были свободны сегодня, они не блокируются.
- Цена мечты ставится один раз, от 1 до 10 000 баллов. Отложить больше цены нельзя. Одновременно не больше 5 мечтаний у дочки (техническое ограничение).
- Собранную мечту дочка покупает кнопкой «Купить мечту». Это покупка, как в магазине: родитель подписывает с Face ID или ПИНом, баллы списываются из копилки этой мечты. Пока покупка ждёт подписи, забрать баллы из этой мечты нельзя.
- Дочка может удалить своё предложение или пустую мечту. Родитель может отменить любую мечту в «Дети», отложенное возвращается и тратится со следующего дня.
- Пуши: родителям о новой мечте (открывает «Подписи»), дочке об ответе и о сбывшейся мечте (открывает «Мечты»).
- Замечание дочек после выкладки: в копилку получалось класть только 5, 10, 20 и «Всё». Теперь число выбирается кнопками − и + с шагом 1, быстрые суммы 5, 10, 20, 50, 100 и «Всё» остались.
- На «Сегодня» под формулой дня строка «Из них в копилке мечты: N»: «Осталось» включает копилку, а потратить её нельзя.
- Общая цель сестёр будет в части 3.
- Проверки: 4 теста базы (предложение и цена, нельзя потратить отложенное и забранное сегодня, покупка мечты с ПИНом, отмена и чужой доступ), 1 сценарий в браузере.

## Этап 4, часть 2: уровни и оценки

- Решения владельца 25.10.2026: баллы, заработанные до этой версии, идут в счёт уровня (уровень и бонус придут в день выкладки). К оценке дочка указывает предмет.
- Уровень считается по всему заработанному: дела, оценки, бонусы (в том числе бонусы за уровень) и исправления родителя. Траты, копилка и подарки уровень не меняют.
- Уровни и бонусы из SPEC: Искатель ракушек (0), Сёрфер большой волны (300, +10), Хранитель острова (700, +25), Капитан звёздного корабля (1300, +50 и сюрприз). Названия не меняются, пороги и бонусы родитель меняет в «Настройки» → «Уровни и оценки». Изменения действуют сразу.
- Уровень достигается один раз и остаётся, даже если родитель потом поднимет порог. Бонус начисляет сервер, один раз за каждый уровень. Если за один раз пройдено два уровня, приходят оба бонуса.
- Сюрприз за последний уровень — от родителей в жизни. Приложение присылает родителям пуш «Приготовьте сюрприз», дочке — «И сюрприз от мамы и папы!».
- Оценка — заявка: дочка выбирает оценку (1–10) или «Похвала учителя или тренера» и пишет предмет или кружок. Недавние предметы предлагаются кнопками. Оценок в день сколько угодно.
- Баллы за оценку берутся из таблицы в момент подписи (SPEC: «со следующей подписи»). Оценка с 0 баллов засчитывается без записи в журнале. «Подписать всё за сегодня» подписывает и оценки.
- Таблица оценок из SPEC: 10 → 10, 9 → 8, 8 → 6, 7 → 4, 6 и ниже → 0, похвала → 5. Каждое значение — от 0 до 50.
- Проверки: 3 теста базы (уровни и бонусы, пороги, оценки и таблица), 1 сценарий в браузере.
- Решение владельца 25.10.2026: мечта стоит около 3 000 баллов, поэтому уровни нужны до 10 000. Пока владелец сам растягивает 4 уровня в настройках (вариант 2). Девять уровней до 10 000 (вариант 1) — вернуться на последнем этапе. При переходе достигнутые уровни сохраняются, пропущенные по новым порогам начислятся сразу вместе с бонусами.

## Этап 4, часть 3: недельные бонусы за серию

- Решение владельца 25.10.2026: из «Недели» остаются только недельные бонусы за серию. Страницы итогов недели, трёх вопросов, звёзд дней и воскресного уведомления нет: в приложении цифры и так видны сразу. Общей цели сестёр нет: девочки хотят зарабатывать каждая сама.
- Серия — свойство дела: «N дней подряд за неделю (пн–вс) → +B». Подряд — без пропуска дня, когда дело есть в расписании: у дела «пн–пт» выходные серию не прерывают. Серия не может быть длиннее, чем дней у дела в неделю.
- Стартовые серии из дневника (SPEC): «Не опоздала в школу» 5 дней, «Сделала уроки сама» 5 дней, «День без ссор с сестрой» 7 дней, по +5. Они ставятся по названию дела, в том числе уже существующим. Родитель меняет серию в карточке дела: «Недельный бонус за серию».
- Когда серия собрана, приложение предлагает бонус родителям (пуш и блок «Недельные бонусы» в «Подписях»). Родитель начисляет или нет. Один раз за дело в неделю. Бонус идёт в счёт уровня.
- Дочка видит на «Сегодня» карточку «Серии недели»: сколько дней подряд уже есть и статус бонуса.
- «Скопировать настройки Есении для Александры» серию не копирует, кроме стартовых серий по названию. Серию для второй дочки родитель ставит в её карточке дела.
- Проверки: 3 теста базы (стартовые серии, серия и её разрыв, пн–пт, подпись, изменение серии), 1 сценарий в браузере.

## Этап 4, часть 4: семья (подарок сестре, семейный договор, день рождения)

- Решения владельца 25.10.2026: подарок сестре до 20 баллов в день (в SPEC было 5). Текст договора берём из бумажного дневника, правки и четыре новых правила владелец дал 26.10.2026.
- **Подарок сестре.** Дочка выбирает сестру и число баллов, сестра принимает, родитель подписывает. Баллы списываются и зачисляются только после подписи родителя. Подпись без ПИНа: ПИН нужен только для покупок (решение 25.10.2026).
- Лимит считается по дню отправки, одна сестра отправляет не больше 20 баллов в день (родитель меняет в «Настройки» → «Подарок сестре»). Изменение лимита действует со следующего дня, как у экранного времени. Лимит 0 выключает подарки.
- Пока подарок ждёт ответа сестры или подписи родителя, его баллы нельзя потратить в магазине или отложить в копилку. Одновременно не больше 5 подарков в ожидании (техническое ограничение). Отправитель может отменить подарок, пока родитель не подписал. Сестра может отказаться.
- В журнале: «Подарок сестре: <имя>» и «Подарок от сестры: <имя>». Подарки не меняют уровень и не считаются заработанными. Пуши: сестре о подарке, родителям о принятом подарке (открывает «Подписи»), обеим о решении родителя, отправителю об отказе.
- **Семейный договор.** 8 правил. Первые из бумажного дневника в редакции владельца 26.10.2026: «Мы честно считаем баллы и не обманываем друг друга.», «Родители не отнимают заработанные баллы и не забывают про подпись.», «Если правило не подходит, мы меняем его вместе и вносим изменения в семейный договор.», «Спор решаем спокойно за 5 минут на семейном совете.» Правило про отметку дел владелец собрал из двух (в приложении нет галочек), по просьбе «объедини»: «Сделал(-а) дело — сразу сам(-а) отметить в приложении. Если нужно — прикрепи фото. Родитель только проверяет.» Слова владельца, добавлено только «сам(-а)» из прежнего «Ребёнок сам…» и «Родитель только проверяет» из прежнего правила. Ещё два правила владельца: «Хочешь что-то купить — используй магазин.», «Копишь на мечту — отложи часть баллов в копилку.» Последнее правило владелец просил изменить и выбрал вариант «перечислить, что подписывают»: «Мама или папа подписывают в приложении дела с проверкой, оценки, покупки, мечты и подарки.» (было «Мама или папа проверят и одобрят.»: в приложении действие называется «подпись»).
- Каждый член семьи (обе дочки, оба родителя) подписывает договор один раз при следующем входе после выкладки. Пока не подписано, остальное приложение закрыто, открывается только экран договора. Подпись хранит имя, роль и дату.
- Родитель меняет правила в «Настройки» → «Семейный договор»: список правил (от 1 до 10, до 200 знаков) и обязательная заметка «что изменилось». Создаётся новая версия, все подписывают заново, записи об изменениях остаются в журнале «Изменения в правилах». Тот, кто изменил, подписывает заново тоже. Дети читают договор в «Я» и не могут его менять.
- Новая семья получает договор с 8 правилами при создании. У существующих семей версия 1 создаётся при выкладке.
- **День рождения.** На «Сегодня» дочка видит поздравление «Тебе N лет». Дата берётся из профиля ребёнка, 29 февраля в невисокосные годы отмечается 28 февраля.
- Бонус на день рождения по умолчанию выключен. Родитель включает его в «Настройки» → «День рождения» и задаёт сумму (1–500). Баллы начисляются один раз в год, когда дочка (или родитель через экран) открывает приложение в этот день. Сервер по расписанию ничего не начисляет. Бонус идёт в счёт уровня, как обычный бонус, и помечается в журнале.
- Текст согласия (редакция 1) не менялся. Новые данные укладываются в его перечень: подписи под договором хранят имя (как зовут родителя или имя ребёнка), роль и дату, подарки и бонус на день рождения относятся к «звёздным баллам», дата рождения в перечне уже есть. Отдельно «семейный договор» в целях обработки не назван. Если владелец захочет назвать его прямо, нужна редакция 2 и новая отметка родителей. Без подтверждения владельца текст не меняется.
- Проверки: 10 тестов базы (подарок, лимит и резерв, отказ и отмена, изменение лимита, пуши, договор, смена правила и повторная подпись, второй родитель и новый телефон, бонус и 29 февраля), 3 сценария в браузере (договор, подарок и настройки, день рождения). Старые сценарии доработаны: после входа подписывают договор.
