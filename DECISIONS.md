# Технические решения

Одна строка — одно решение: что выбрано и почему.

## Этап 1. Каркас

- Expo SDK 57 и Expo Router, веб-сборка `output: single`. Один index.html, экраны рисуются на телефоне, сервер для страниц не нужен.
- Адрес подпапки `/<repo>` задаётся при сборке через `EXPO_BASE_URL`. GitHub Pages публикует проект по адресу `имя.github.io/<repo>/`.
- `404.html` — копия `index.html`. GitHub Pages отдаёт её на любой адрес внутри приложения, и открывается нужный экран.
- Service worker собирается из `sw/sw.ts` через esbuild и Workbox `injectManifest`. Нужен свой код для пушей на этапе 2, готовый `generateSW` его не допускает.
- Новая версия service worker включается сразу и показывается при следующем открытии приложения. Так требует раздел 10.
- Клиент только читает данные под правилами RLS. Все записи идут через функции Postgres с проверкой роли. Так ребёнок не может ничего изменить напрямую.
- Привязка телефона `pair_device` — функция Postgres, а не Edge Function. Это одна транзакция и не нужен отдельный деплой. Edge Functions понадобятся для пушей и Face ID.
- Код привязки: 6 цифр из криптостойкого генератора, в базе хранится только хеш SHA-256. Код одноразовый, живёт 10 минут, работает только последний выданный.
- Защита от подбора кода: не больше 5 неверных попыток за 10 минут с одного телефона и 50 со всех.
- `pair_device` возвращает ошибку в ответе, а не исключением. Иначе откатилась бы запись о неудачной попытке и защита от подбора не работала бы.
- Телефон ребёнка входит анонимным аккаунтом Supabase. Почта ребёнку не нужна, вход постоянный.
- Отвязка телефона удаляет его анонимный аккаунт. Доступ к данным пропадает сразу, сессия телефона перестаёт обновляться.
- Родитель входит по 6-значному коду из письма. Ссылка из письма открылась бы в Safari, а не в установленном приложении.
- В Supabase меняются два шаблона письма: «Confirm signup» для первого входа и «Magic Link» для следующих. На локальном стенде проверено: при первом входе приходит письмо подтверждения.
- Имена и даты рождения детей не записаны в код. Родитель вводит их при создании семьи, потому что репозиторий публичный.
- `SPEC.md` исключён из репозитория через `.gitignore`. В нём данные семьи.
- Comfortaa — только для надписей заглавными буквами, заголовки набраны Nunito ExtraBold. Строчные кириллические «д, т, и, п» в Comfortaa похожи на «g, m, u, n» и мешают детям читать.
- Шрифты подключаются по отдельным начертаниям, всего 6 файлов. Иначе в сборку попадали все начертания и приложение весило на 2 МБ больше.
- Подпись под значком на экране «Домой» — «Звёзды». Полное «Звёздные баллы» iPhone обрезает.
- Увеличенный шрифт iOS: страница получает системный шрифт `-apple-system-body`, приложение читает его размер и увеличивает свои шрифты до 1,6 раза.
- Подтверждения «Отвязать», «Выйти» и «Удалить» — свои окна в приложении. Системные `alert` в веб-версии React Native не работают.
- Удаление семьи требует ввести слово УДАЛИТЬ. С этапа 3 к нему добавится Face ID или ПИН.
- После входа родитель попадает на вкладку «Дети». На этапе 1 заявок ещё нет, со 2 этапа стартовой станет «Ждут подписи».
- Ребёнок видит записи родителей (понадобится для «Подтвердила мама»), но не видит профиль и телефон сестры.
- «Сегодня» считается на сервере по часовому поясу семьи Europe/Minsk. Поэтому дату рождения нельзя поставить в будущем.
- Окно «Код для телефона» понимает, что телефон подключился, по времени привязки на сервере. Подсчёт телефонов давал гонку, если ребёнок вводил код очень быстро.
- Локальный стенд для проверок: настоящие Supabase Auth v2.195.0 и PostgREST v12.2.3 со встроенным Postgres. Так всё проверяется до подключения настоящего проекта.
- Сборка и публикация — GitHub Actions и `actions/deploy-pages`. Отдельная ветка `gh-pages` не нужна.
- Адрес и публичный ключ Supabase хранятся в переменных репозитория GitHub, а не в коде. Публичный ключ виден в приложении по замыслу Supabase, данные закрыты правилами RLS.
- Встроенная почта Supabase шлёт письма только адресам команды проекта и не больше 2 в час. Для этапа 1 хватает почты владельца, для второго родителя на этапе 2 нужен свой почтовый сервер.
- Приглашение второго родителя перенесено на этап 2. Его нет в списке этапа 1, и ему нужна настройка почты.
- Face ID и ПИН родителя — этап 3, как в разделе 11. Модули `src/platform/push` и `src/platform/biometric` уже выделены с одним интерфейсом.
